# ProofGraph v1.1.0 — OpenCode and Pi first-class hosts

## Highlights

- OpenCode promoted to the primary ProofGraph host.
- Pi promoted to the reference TUI host.
- Added versioned `proofgraph.host.v1` command, event, and tool-policy protocol.
- Added bearer-authenticated loopback HTTP/SSE Host Bridge.
- Added managed project/user installers for OpenCode plugins and Pi extensions.
- Added OpenCode Server execution host with structured output, session abort, and diff artifacts.
- Hardened Pi strict JSONL RPC execution and non-interactive UI handling.
- Required Pi `agent_settled` as the sole final completion event; `agent_end` is diagnostic only and early process exit fails closed.
- Added fail-closed tool-policy interception in both hosts.
- Added independent black-box, adversarial, installer, CLI, and mock end-to-end verification.
- Added deterministic `@proofgraph/host-opencode` and `@proofgraph/host-pi` package archives.
- Corrected the OpenCode global SSE endpoint to the official `/global/event` path and pinned it with a regression test.
- Removed approval, denial, and abort from the OpenCode model-callable tool surface; operator actions now use the ProofGraph CLI path.
- Required a dedicated operator-confirmed `opencode --pure serve` worker to prevent plugin recursion.
- Stabilized the Host Bridge startup handshake as one JSONL record without echoing provided bearer tokens.
- Pinned every Host Bridge instance to one configured host identity and reject cross-host impersonation.
- Denied approve, deny, and abort through the OpenCode Host Bridge even with a valid bearer token; human-gate actions require the ProofGraph CLI/operator path.

- Hardened the OpenCode managed installer to merge and pin `@opencode-ai/plugin@1.18.4` in the config-root package manifest without deleting user fields.
- Added transaction-style staging, backup, rollback, dependency-conflict, and package-manifest symlink tests for Host installation.
- Recorded reviewed contract targets for OpenCode 1.18.4 and Pi 0.82.0; Pi Host usage requires Node.js 22.19.0 or newer.
- Added exact-version live-preflight checks while preserving the release status as offline-verified until authenticated canaries pass.
- Fixed result-field precedence in live preflight so an unreviewed but executable Host version fails instead of inheriting the subprocess success flag.

## Release gate

`PASS_OFFLINE_OPENCODE_PI_CANARY_REQUIRED`

OpenCode and Pi binaries were not installed in the release environment, so authenticated live vendor canaries remain mandatory before production eligibility.
